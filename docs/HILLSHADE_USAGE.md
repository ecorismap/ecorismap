# 陰影起伏図(全方位対応) の使い方

地図一覧では「陰影起伏図(全方位対応)」として表示されます。
既定で入っている「陰影起伏図」は地理院が配信する完成品のラスタタイルで、別物です。

標高タイルから地形の陰影を計算して表示する機能です。
派生機能の陰影段彩図（`relief://`、海域対応）は[後半の節](#陰影段彩図relief)を参照してください。

従来の陰影起伏図は光源方位に依存するため、地図を180度回すと凹凸が反転して見えました。
また光源と平行な走向の谷は明暗差を持たず、構造的に見落とされる弱点もありました。
現在の方式は式に光源が現れないため、**地図をどの向きに回しても見え方が変わりません**。

## 使い方

地図設定画面の URL に `hillshade://` を付けて標高タイルの URL を指定します。
プリセットは産総研の海陸統合DEM（`elev/mixed`）を使っており、海底地形にも陰影が出ます。

```
hillshade://https://tiles.gsj.jp/tiles/elev/mixed/{z}/{y}/{x}.png
```

- 濃さは透過スライダーで調整します
- 「固定ズーム」は標高タイルが実在する最大ズームに合わせてください（産総研のタイルは陸域15）
- 海域のデータが信頼できるのはz8までのため、ズーム9以上では海の陰影は不正確になったり
  透明になったりします（陸の陰影はz15まで正確）。海域の詳しい事情は後述の陰影段彩図の
  節を参照。陸域のみでよければ `elev/land` も引き続き使えます

計算内容は光源を使わない立体図に変わりましたが、プレフィックスは `hillshade://` のまま
据え置いています。ユーザーが追加済みの地図・エクスポート済みの地図JSON・共有プロジェクトの
設定に既に埋め込まれており、変えると認識されず標高タイルの生の色が表示されるためです。

## 対応する標高タイル

**国土地理院・産総研方式のみ**に対応しています。

```
x = 2^16·R + 2^8·G + B
NoData は 2^23（透明にする）
標高[m] = x < 2^23 ? x/100 : (x − 2^24)/100
```

Mapbox Terrain-RGB や Terrarium 形式には対応していません。

## 陰影の計算方法

MPI赤色立体地図（Kaneda and Chiba 2019）を無彩色化したもので、
**2つの「暗さ」の掛け算**です。

```
MPI  = 各方位(8本)について半径16px以内の最大仰角を求め、その平均[度]
傾斜 = 中央差分による勾配の大きさ[度]

s = clamp(傾斜 / 55°)
m = clamp(MPI / 25°) ^ γ        （γ = 1）
明度 = 255 × (1 − s) × (1 − m)
```

MPI（Morphometric Protection Index、保護指数）は「周囲の地形にどれだけ囲まれているか」
を表します。谷底は周りが高いので各方位の仰角が大きく MPI が大きくなり、
尾根や平坦地は周りが低いか同じなのでほぼ 0 か負になります。

| 地形 | 見え方 |
|---|---|
| 急峻な谷 | 両方効いて最も暗い |
| 急な尾根 | 傾斜だけ効いて中間 |
| 平坦な谷底 | MPIだけ効いて中間 |
| 平坦な尾根・台地 | どちらも効かず白 |

探索半径は画素固定の 16px です。z=14（約 9m/px）で約 145m となり、
MPI赤色立体地図で推奨される実距離 150m とほぼ一致します。画素固定なので
1タイルあたりの計算コストがズームによらず一定になります。

## 実装

| プラットフォーム | 実装 |
|---|---|
| 計算（Web） | `src/utils/terrainShading.ts` |
| タイル生成（Web） | `src/utils/shadingTileProtocol.web.ts`（maplibre の `addProtocol`、内部プロトコル `terrainshade://`） |
| Android | `MapDEMTileProvider.java`（`patches/react-native-maps+1.27.2.patch`） |
| iOS | `AIRGoogleMapDEMTileOverlay.m`（同上） |

3プラットフォームとも同じ計算をしています。**変更するときは3つとも揃えてください。**
移植が正しいことは、同一の合成地形に対する出力を突き合わせて確認しています
（4096画素すべて完全一致）。

Web では maplibre 内蔵の hillshade レイヤは使いません（光源方位に依存するため）。
標高タイルを自前で取得・デコードし、陰影を計算した通常のラスタタイルとして返します。

いずれのプラットフォームでも共通する要点:

- 探索半径のぶんの袖が要るので、1タイル描くのに**周囲8タイルの標高を参照**します。
  デコード済みの標高をキャッシュするので、実質1枚あたり1回の取得で済みます
- NoData と取得失敗は透明にします
- オーバーズーム時は標高が実在する最大ズームで計算してから切り出して拡大します
- **標高タイルの提供範囲には地域差があります。** 産総研の陸域統合DEMは仕様上z19まで
  ですが、実測ではz14が全国、z15は佐渡島・知床・屋久島などで欠け、z16以上は東京都と
  高知県のみでした。要求されたズームで取れないときは粗いズームへ降りて切り出すので、
  「固定ズーム」を高めに設定しても白抜けにはなりません（そのぶん解像度は落ちます）

オフライン用にダウンロードされるのは**陰影の計算結果ではなく生の標高タイル**です。
表示のたびに計算します。

## 注意

- 平坦地は白になります。乗算で重ねる前提の図なので、ベースマップに重ねるより
  単体（透過 0）で背景として使う方が本来の姿です
- ネイティブのパッチを変更したら `npx patch-package react-native-maps
  --exclude '(^|/)(\.gradle|build|\.cxx)/'` で再生成してください。
  除外を付けないと `node_modules` に残ったビルド生成物を巻き込みます

## 陰影段彩図（relief://）

hillshadeの派生機能です。URLに `relief://` を付けると、同じ陰影計算に加えて以下を行います。
プリセットは後述のGEBCOスタイル（「GEBCO海底地形図(全球)」）のみですが、
既定スタイルもURLの手動指定でそのまま使えます。

```
relief://https://tiles.gsj.jp/tiles/elev/mixed/{z}/{y}/{x}.png
```

- **段彩**: 標高から色を引く（深海=青 〜 海岸=明るい水色 〜 陸=緑 〜 茶の区分線形補間、
  0mに意図的な不連続）。深海が陰影・等深線と重なっても潰れないよう明るめに寄せてある
- **海岸はベース地図優先**: 海に接する陸画素（境界の1画素、斜め隣接含む）は透明にする。
  海陸統合DEMは海岸線付近で陸のデータが優先され、粗いズームでは近海が陸として
  塗られてしまうため、境界帯を透明にして下のベース地図の正確な海岸線を見せる
- **陰影**: 係数 (1−s)(1−m) をそのまま掛けず、下限付きで緩和して掛ける
  （`RELIEF_SHADE_MIN + (1−RELIEF_SHADE_MIN)×shade`、下限0.35）。
  急峻な深海が黒く潰れないようにするため。hillshadeの無彩色陰影には影響しない
- **等深線**: `floor(標高/間隔)` が右隣・下隣と異なる画素を暗くして焼き込む。
  間隔は計算を実行したズーム（sourceZoom）で決まる（z4:[500,5000] 〜 z9以上:[50,200]、
  z4未満は引かない）。太線間隔が優先。ラベルは付かない
- 隣が陸またはNoDataの画素には線を引かない（0m等深線は引かない）
- **GEBCOスタイル**: URLのフラグメントに `#style=gebco` を付けると、
  shiwaku氏のGEBCOデモ（gebco-2025-grid-tile-on-maplibre）を再現するモードになる。
  プリセット「GEBCO海底地形図(全球)」で使用
  （`relief://https://tiles.gsj.jp/tiles/elev/gebco/{z}/{y}/{x}.png#style=gebco`、
  GEBCOは全球・z9まで・約450mメッシュ）。フラグメントは標高タイルの取得時には落とされる
  - **Web**: デモと同一構成をmaplibreの実レイヤで描画する（`src/utils/gebcoDemLayers.web.ts`）。
    `gsjdem://`プロトコルでGSJ数値PNGをTerrain-RGBへ変換してraster-demソースにし、
    color-relief（指数補間0.8・不透明度0.85）＋内蔵hillshade（光源315°・exaggeration 0.6）
    ＋maplibre-contourの等深線ベクタと**数値ラベル**を重ねる。等深線のしきい値もデモと同値
  - **ネイティブ（iOS/Android）**: 同じ見た目のラスタ近似
    （TS参照実装は`colorRelief.ts`の`computeGebcoRelief`）。指数補間の段彩を白と0.85:0.15で
    混合し、**maplibreのhillshadeシェーダ（standard法・prepareのderivスケール込み）を
    そのまま移植**して合成、海陸両方に等値線を焼き込む。主要等値線には数値ラベルを
    水平配置で焼き込む（128px格子に1つ・タイル端16pxは避ける。線に沿う配置や
    タイル間の衝突回避はできない点がWebとの差）
  - **島名・海底地形名（海しる由来）も地図に同梱**され自動表示される（z4〜15、
    小さい黒点＋白フチの名前）。Webは`src/presets/data/msil_*.json`をGeoJSONソースとして
    重ねる。**ネイティブはタイル焼き込みではなくMarkerオーバーレイ**
    （`src/components/organisms/HomeSeaLabels.tsx`＋選定ロジック`src/utils/seaLabels.ts`）で、
    画面空間のネイティブ文字描画のため鮮明・正立・タイル境界切れなし。
    間引きはワールドピクセル格子（整数zoomで128px格子に1件、上限50件）で、
    世界座標に固定されているためパン中にラベルが飛ばない。
    データ更新は fetch-msil-data.js の再実行のみ
  - ネイティブの**等値線の数値ラベルもMarkerオーバーレイ**（`src/utils/contourLabels.ts`）。
    タイルに焼き込むのは線のみで、ラベルはJS側で同じGEBCOタイルを取得・デコード
    （可視領域計算と同じ loadDemTilePng + decodeDemTile）し、焼き込みと同一の横断判定・
    同一のsourceZoom（表示zoomをz9でクランプ）で太線の位置を求めて置くため、
    描かれた線の上に正確に乗る。間引きは地名と同じワールド格子（上限40件）
  - **オフライン（ネイティブ）**: 地図のダウンロード機能で生のGEBCO DEMタイル
    （z0〜固定ズーム）が保存され、タイル表示は機内モードでも動く。数値ラベルの計算も
    ダウンロード済みタイル（`TILE_FOLDER/{地図id}/z/x/y`）を優先して読むため、
    ダウンロード範囲内ならオフラインで表示される（範囲外はDEMローダーの
    ディスクキャッシュに残っていれば表示）。地名は同梱データなので常にオフラインで動く。
    Webはアプリ全体としてオフライン非対応
  - このモードでは海岸の透明化は行わない（デモ同様、陸もGEBCOの標高で段彩される）
  - **elev2系のWebP/512pxソースも指定可能**（例: 内閣府 南海トラフ地形データ
    `relief://https://tiles.gsj.jp/tiles/elev2/caonankai/{z}/{x}/{y}.webp#style=gebco`、
    z11まで・整備域は南海トラフ広域で外は透明）。
    Webは`gsjdem://`変換とmaplibre-contourの`fetchAndParseTile`差し替えがそのまま読み、
    **親タイル補完**でタイル欠損・NoDataを粗いズームから埋める（残るNoDataは
    Terrain-RGB最大値を番兵にしcolor-reliefのstep式で透明化。等値線はNaNセルを
    スキップするので整備域の縁で自然に途切れる）。ネイティブのデコードは
    BitmapFactory/UIImage任せで、出力は実寸タイル（Android=512px Tile、
    iOS=scale2のUIImage）。数値ラベルのJS計算はexpo-image-manipulatorで
    WebP→PNG変換してからpngLiteで読む。ネイティブはNoDataがそのまま透明

デコード・袖組み立て・ズーム降格・オフラインDL（生DEM保存）はhillshadeと完全に共通です。
対応する標高タイルの形式も同じ（地理院・産総研方式のみ）。

段彩テーブルと等深線間隔の**単一情報源は `src/utils/colorRelief.ts`**。
Android（`MapDEMTileProvider.java` の `RELIEF_RAMP` 等）と
iOS（`AIRGoogleMapDEMTileOverlay.m` の `kReliefRamp` 等）には同じ値をハードコードしており、
一致は `colorRelief.test.ts` のパッチ整合テストで機械検証されます。
**値を変えるときは3実装を揃えてパッチを再生成**してください。

既定スタイルで海陸統合DEM（`elev/mixed`）を使う場合の注意: 陸域はz15まで実在しますが、
**海域のデータが信頼できるのはz8まで**です（2026-08実測）。z9では地域によって
海面に陸ソース由来の正の値が混入し（例: 仙台湾はほぼ全面が正値になり陸色で塗られる）、
z10ではタイルは存在するものの海が全てNoDataになります。正値の海は海岸優先の
浸食判定（負値の隣接判定）も効かないため、固定ズーム（overzoomThreshold）は
**8**を推奨します（z8≒460m/px。海の元データは250〜500mメッシュなので
実質的な情報損失はない。z9以上の表示はz8計算結果の拡大）。
