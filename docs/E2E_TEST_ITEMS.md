# E2Eテスト項目台帳（機能一覧）

EcorisMapが備えている機能を、正常系のテスト項目として一覧にしたもの。
1行が1機能で、Web / iOS / Android のそれぞれでどう確かめるか（自動か手動か）を示す。
リリース前にテストするものは、すべてこの台帳にまとめてある（「リリース前にやること」の順に通す）。
人が確かめる必要があるのは「手」の行だけで、「シミュ」「機」は人の手を借りずに確かめられる。

- リリースごとの結果はここには書かない（チェック欄は手順の目印で、埋めてコミットしない）
- 機能を足したら行を足し、消したら行を消す。自動テストを書いたら「シミュ」「機」を「自」に変えてパスを入れる
- 監査で直した細かい不具合の再確認項目は `docs/DEVICE_CHECKLIST_2026-11.md` にある（備考にIDで参照）

## 記号

| 記号 | 意味 |
|---|---|
| 自 | 自動テストがある（「自動テスト」列のファイル） |
| シミュ | 自動で確かめられる見込みだが、まだテストが無い。Webはブラウザ、iOS／Androidはシミュレーター／エミュレーターで足りる |
| 機 | 実機をMacにつなげば自動で確かめられる見込みだが、まだテストが無い（カメラ・GPUなど、シミュレーター／エミュレーターでは確かめられないもの） |
| 手 | 人が確かめる（持ち歩いての移動・センサー・外部の機器・本番のアカウントや外部サービス・複数人での操作が要る） |
| — | その端末には機能が無い |

「ログイン」列: 空欄＝不要、要＝組織アカウント、Drive＝Google連携。

「シミュ」「機」の考え方:

- 人の手が要らないものを指す。自動テスト（Playwright・Maestro）にするか、Claudeが端末を操作し、
  画面・スクリーンショット・ログを見て確かめる。地図の絵のように機械的に判定しにくいものは後者になる
- 「シミュ」「機」は見込みで、実際に流して確かめたものではない。自動テストを書いたら「自」に変える
- テストが無いあいだは、リリース前に端末を操作して確かめる
- iOS／Androidの「要」の行は、開発ビルドをFirebaseエミュレータにつないで確かめる
  （`EXPO_PUBLIC_USE_FIREBASE_EMULATOR=1`。Webの `yarn e2e:web:emu` と同じく暗号化は使わない）。
  ネイティブではまだ試していない。本番のアカウント・暗号化（Virgil）・Google連携が要るものは「手」
- 本番のパスワード・PINの入力と、Googleへのサインイン・許可は、Claudeは行わない（人が行う）。
  人がログインや連携を済ませた実機なら、そのあとの操作は「機」で確かめられる
- ファイルの取り込みは、テスト用のファイルを端末へ送り（`adb push`／`xcrun simctl`）、OSのファイル選択から選ぶ
- 「機」のAndroidは `DEVICE=<シリアル> scripts/e2e-native.sh android` で実機へ流せる。
  iOSの実機でMaestroが使えるかは未確認で、使えなければClaudeが実機を操作して確かめる

## リリース前にやること

ストアへ提出する前に、上から順に通す。ユニットテストはネイティブモジュール
（expo-media-library、expo-image-picker、expo-file-system など）をモックしているので、
ライブラリの更新で入口の挙動が変わった種類の不具合は検出できない。
Expo／React Nativeのメジャー更新を含むリリースでは、4 と 5 を特に落とさないこと。

### 1. 型・リント・ユニットテスト

- [ ] `npx tsc --noEmit`
- [ ] `yarn lint`（`expo-media-library` のルートimport禁止ルールを含む）
- [ ] `yarn test`

### 2. 自動テスト（「自」の行）

| | 対象 | コマンド | 前提 |
|---|---|---|---|
| [ ] | Web（未ログイン範囲） | `yarn e2e:web` | 開発サーバーは自動で起動する（起動済みなら使い回す） |
| [ ] | Web（ログイン範囲） | `yarn e2e:web:emu` | Firebaseエミュレータ（Java 21）の起動から片付けまで行う。暗号化（Virgil）は使わずに画面の流れを確かめる |
| [ ] | サーバー側の通し（同期・権限・写真） | `yarn testrules` | Firebaseエミュレータ（Java 21） |
| [ ] | iOSシミュレーター | `yarn e2e:ios` | 下の「ネイティブの前提」 |
| [ ] | Androidエミュレーター | `yarn e2e:android` | 同上。エミュレーターは先に起動しておく |
| [ ] | データをクリア→自動バックアップから復元（SET-2・SET-3） | `scripts/e2e-native.sh ios 90` ／ `scripts/e2e-native.sh android 90` | 端末のデータを消すので、上の2つでは流れない。テスト専用の端末で流す |

iOSとAndroidは同時に流さず、順番に実行する。

ネイティブの前提:

- Maestroのインストール: `brew install mobile-dev-inc/tap/maestro`（Homebrew標準の `maestro` は別製品）
- 端末はログインしておらずプロジェクトを開いていない状態で、言語は日本語であること。
  既定の「ポイント」レイヤにテスト用の記録を作って最後に消す（すでに記録があっても動く）。途中で失敗して残ったときは
  `maestro test e2e/maestro/photo/99-delete-all-test-records.yaml`（レイヤの全記録を消すのでテスト専用の端末でのみ）
- デバッグビルドで回すときはMetro（`yarn start`）を起動しておく
- Androidは、実機がつながっていても `DEVICE` を指定しない限りエミュレーターにだけ流す
- 写真の経路だけ流すときは `yarn smoke:photo ios <ビルドした ecorismap.app のパス>` ／ `yarn smoke:photo android`
  （iOSは .app を渡すと入れ直しを挟み、データコンテナが変わっても原画で開けることを確かめる）
- クリア→復元を全フローと一緒に流すときは `E2E_ALLOW_CLEAR=1 yarn e2e:ios`。
  復元で記録は戻るが、地図の設定は初期化され、自動バックアップは5世代までなので古い世代が1つ押し出される
- 画面要素は `testID` で特定している（一覧は `e2e/TESTIDS.md`）。消したり名前を変えたりしたらテストも直す

### 3. まだテストが無い行（「シミュ」「機」の行）

- [ ] 「シミュ」の行を、Web・iOSシミュレーター・Androidエミュレーターで通した（Claudeに任せられる）
- [ ] 「機」の行を、Macにつないだ実機で通した（Claudeに任せられる。人は端末をつなぐ）

### 4. 人が確かめる行（「手」の行）

- [ ] 「手」の行を、人が端末で通した（iOS・Android・Web）

### 5. 過去に実際に壊れた経路

ユニットテストも自動テストも届かず、実際に壊れたことがある。記号にかかわらず、実機で必ず通す。

- [ ] **写真**（PHOTO-A2・A3）: カメラボタンで撮影 → サムネイルが出て保存ボタンが有効になる → 保存 → 開き直して写真が残り、カメラロールにも入っている
      （0.6.0〜0.6.7で `expo-media-library` の入口変更により保存されなかった。CHANGELOG 0.6.8）
- [ ] **Android・写真**（PHOTO-A4）: 開発者オプション「アクティビティを保持しない」をONにして撮影 → 編集画面が開き直り写真が付いている
      （復帰は `usePendingPhotoCapture` ＋ expo-modules-core のパッチで実現）
- [ ] **軌跡**（TRACK-2）: 15分以上、画面OFFのまま移動し、アプリを開き直しても記録が途切れず点が重複しない
      （位置情報ライブラリ react-native-background-geolocation を更新したリリースでは必須）
- [ ] **PMTiles・外部GNSS**（MAPS-7、GNSS-1〜7）: Android は R8 ビルド（リリースビルド）で確かめる
- [ ] **3D・眺望**（ANLY-3〜9）: Android は実機で必ず確かめる（エミュレーターとGPUが異なる）。しばらく操作して極端なカクつき・発熱・クラッシュがない
- [ ] **回転**（MAP-2）: 回転中も現在地マーカー・線の矢印が実際の方角を向く。作図・ツール使用中は回転しない
- [ ] **認証・同期**（ACCT-1・7、PROJ-5・6、DRIVE-1〜3）: ログイン（Google／組織アカウント）とログアウト、プロジェクトの送信・取得（暗号化の往復）

### 6. テスト以外

- [ ] アプリ内の「更新情報」が今回の内容になっている（OS固有の修正は載せない）
- [ ] `CHANGELOG.md` の日付を確定した
- [ ] マニュアル（websiteリポジトリ）の追従が必要なら反映した
- [ ] バージョン・ストア申告は `docs/STORE_SUBMISSION_ANALYTICS.md` の「提出時チェックリスト」
